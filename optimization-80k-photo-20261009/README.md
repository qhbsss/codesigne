## 目标与方法

不改固定 Transformer、输入输出、公共评估器、成本模型或 baseline。分数为

`S = 1000 * sqrt(30996995 * 1302032 / (TP * TD))`。

80k 要求 `TP*TD <= 6306106155.2875`，比当前乘积减少 36.254%。例如 TP=250000、TD=25000 才能约 80358 分。这只是预算，不能代替实际完整 grade。

参考图片测试寄存器保留中间结果、16 列分块、加载计算重叠、按实际数据事件启动消费者。约束包括面积<=24 mm²、1000 周期窗口峰值功耗<=20 W、每SM最多4驻留组、每组64KiB RF、每个操作数不能跨bank、DMA容量和HBM真实生产消费依赖、每程序8MiB，以及D1逐步STEP.COMMIT。

## 代码大小与语义

`p1-w2-four-m8-guarded` 将每个16行W2 MAC拆为两个独立M8累加器。直接展开代码9142589字节，不合法。原来的尾部预取消除把整个循环复制成“非末块+末块”，这里换成每条下一块LD的0/1次循环：末块0次，其余1次。

`reports/p1-w2-four-m8-guarded-tail-equivalence.json` 对比同一生成源码下的新保护循环与旧尾部展开，公共ISA展开后的109830条指令逐条比较 opcode 和完整 operands/events 相等。只有文本与行号不同，不能把此文本压缩当作周期收益。合法版本为6860586字节。

候选ASM不重复纳入Git，可在候选目录运行：


## 粗估与完整精评

旧筛选辅助工具遗漏WAIT，已在本目录辅助工具中将WAIT与BARRIER/STEP.COMMIT一样计为控制同步；未修改公开模块。此粗估忽略具体事件依赖和multicast实际发射时刻，不能作为正式分数或功耗证明。以63872完整报告校准，`d1-specialized48` 中心粗估61327.87，10%不确定度下保守55752.25，不通过80000门槛。完整grade实际得到64214.04366988358，粗估偏低约4.49%；两者都没有达到80000。这进一步说明粗模型只能筛选，不能代替调度器。

`project/bind_trials.py` 生成候选源码、程序、公共模块和原始报告SHA256绑定。`python -m project.verify_trials` 检查绑定并逐字节重生成所有候选。原始失败、超尺寸和无改善方案都保留，不将局部测量拼成双案例分数。

## 预取失败的关键原因

未来层只加载权重也会被全体BARRIER纳入：不能仅在图上画“权重加载与计算重叠”。当前层的屏障应只约束它的实际参与者，未来层消费者仍等待当前层真正的HBM结果。56组版将第0层FFN未来组排除在第0层屏障之外，并把同层WO参与者的预取放在真实res写入之后；双种子竞争检查通过，但33699周期仍不够好。所有预取节奏由实际LD/ST事件组成，没有修改时钟或插入虚构等待事件。

D1 48组版的初始步11150周期、后续约3025..3087；56组宽FFN版初始步14221周期、后续约3004..3085。宽FFN并没有大幅压缩暖态关键路径，却增加了冷启动。这是下一次重新分工需要首先证明的问题。
