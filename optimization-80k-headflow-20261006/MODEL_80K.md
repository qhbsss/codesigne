# 对八万分目标的约束补充

完整最高已评结果为 63872.93194880659 分。目标是满足所有门限后最小化 TP×TD，而不是累加局部核函数的提速。

## 指令与资源模型

对 MMA(m,n,k)，阵列 pm×pn、K 并行度 kp、阵列数 c：

- TC 服务时间：2 + ceil(log₂ kp) + ceil(ceil(m/pm) ceil(n/pn)/c) ceil(k/kp)。
- RF 读取量：4 [ceil(n/pn)mk + ceil(m/pm)kn + mn] 字节。
- RF 写入量：4mn 字节。

8R4W 下 RF 读/写服务分别为 128/64 B 每周期。即便数学乘法次数相同，改变分块也会改变 RF 复制读量、输出重复读写和指令启动次数。一个累加器的下一次读还要等待上一次写完成；独立累加块能够增加流水重叠。一个 SM 的 TC、RF、DMA、NoC 等资源还必须遵守互斥日历。

私有 RF 每组 16384 float。vector16 有 16 个 bank，每个 1024 float；vector8 有 8 个 bank，每个 2048 float。后者不是增加总容量。旧的逻辑 bank l 映射到物理 bank floor(l/2)，offset 加 (l mod 2)×1024。合法单操作数还必须满足 bank 内视图边界。更大 C 块只有在 A、B、临时值和偏置的存活区间可共用空间时才有意义。

示例 W1 N64：256×64 权重占 16384 float，不能在 RF 内同时保存输入与输出。因此保存三块 N16 权重共 12288 float，另一块 4096 float 放 SH。SH→RF 仍需要 DMA 队列、SH 端口和 RF 写端口，不是免费访问。单组输入复制量从 N32 的 32 组降为 N64 的 16 组，但新的 RF/SH 服务可能抹去收益，单行实测已否定这个简单方案。

## 依赖与在线条件

数据依赖必须覆盖全部生产者写事件；不能只拿最后一条 ST 代替跨组全部完成。BARRIER 除显式依赖外，还等待所包含组的未完成指令与 DMA；WAIT(wg, events) 只等待指定事件，可避免等上一行存储，但必须由真实数据依赖保证合法。

D1 每个 STEP.COMMIT 后才释放下一步输入；P1 新位置输入也不能提前读取。因此把 P1 每层 prompt 和其新位置一起执行，会违反在线输入条件。权重可以预取，但不能提前计算未知输入。

HBM multicast 按同周期、同缓存行判断。减少 barrier 后，消费者 LD 的发起周期不同，原来一次源读取可能变成多次源读取，导致延迟与功耗上升。固定 HBM 带宽下的载荷下界不能用某一图的 busy_cycles 直接代替所有图的下界。

## 面积、功耗与评分

每个 SM 至多 4 个驻留组。SH 配额按 SM 内各组求和，不可跨组共享私有 SH。总面积 ≤24 mm²；精评的 1000 周期滑动功耗峰值 ≤20 W。8 通道 HBM 满载时源读取动态功耗已接近 19.2 W，再加静态和 RF/NoC/TC 能量就可能超限，平均功耗较低不能证明峰值合格。

评分 S=1000√(30996995×1302032/(TP×TD))，八万要求 TP×TD≤6306106155.2875。目前 303331×32613=9892533903，仍需下降 36.25%。若 D1 固定 32613，P1 需≤193361 周期；若 P1 固定303331，D1需≤20789周期。250000/25000、260000/24000 是达到目标的周期预算，没有验证出对应实现。

此外每份 ASM ≤8388608 字节；raw grade 的硬件与程序必须对应保存的源码和实际受评哈希。不能拼接局部计时作为总分。

## 应优先验证的较大改动

1. 让矩阵计算拥有足够多独立 C 块，减少同一 C 的串行反馈，同时用 bank 存活区间复用 A 和 GELU 临时区。必须评估 RF 重复读、SFU 变窄与 DMA 排队，不能只数 MAC 指令。
2. 把 QKV、注意力、WO/归一化、FFN 的行块输出通过真实事件连接，在驻留预算内建立跨阶段流水。先计算各角色所需权重、KV 和临时区，再决定哪些角色能共组；共享角色在等待下一阶段时不能阻断未来生产者。
3. 用实际写入和 MAC 事件约束预取波，保留 multicast 对齐，测量完整冷启动和全部在线步骤。此前生产者统计共享、每层专用 FFN、四段 RF 注意力都已测得无收益或超功耗，不应继续把它们当作已经成立的大方向。

FFN 简单融合有反例：每个 W1 K32 输出组直接计算 W2 全列部分和，原 W2 四个 K256 部分和会变成32个K32部分和，部分和 HBM 写读流量增加8倍。必须扩大 K 归并或找到合法消费者复用方式，才可能有总收益。
