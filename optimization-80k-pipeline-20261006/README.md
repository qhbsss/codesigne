# 八万分方向实验（2026-10-06）

当前最高完整、eligible=true 的公开本地精评为 **62982.582322132635**：P1 310786 cycles，D1 32737 cycles；峰值19.6263663475/19.7697766185W。原始报告与冻结版本见 `../final-optimized-62982-20261006`。尚未达到八万分。

评分：S=1000√(30996995×1302032/(TP×TD))。八万分要求乘积≤6306106155.2875，当前需减少39.41%。可行目标组合如TP=245000、TD=25000，对应81174.12分；这只是目标预算，不是性能预测。单独保持D1=32737时，P1需≤192629，低于原固定指令图资源下界193874，所以应改变图或同时改善D1。

本轮候选仅改变生成器、硬件或布局。公开评估器、参考数学、成本模型和baseline保持原样。功能检查包含数值与HBM竞争；局部计时和下界不记作完整成绩。

W1 N64流式方案的关键与先前SH溢出方案不同：无需所有K权重同时常驻。128row×64col累加器=8192floats，占8bank；K64×N16的四个权重面板占4bank；M16×K64的A占1bank，仍有3bank用于参数和临时量。每个K分块加载一次权重、遍历全部行；同一输出的K累加顺序保持不变。W1输入A的NoC递送由32份降到16份，3层理论减少6MiB递送；RF读需求本身未减半，TC按8×16阵列重复读取A/B，不能用数据量减半推导耗时减半。跨行块独立累加器也可能减少累加依赖等待。初版在W1之后填W2 bank，有额外串行加载成本；若功能与局部时间有潜力，再用真实MAC事件把W2填充提前。

跨层预取失败说明“更多重叠”不总是有效：新流量占用相同HBM/NoC/DMA资源，且峰值是1000周期窗口能量。参考结果并没有修改或换seed。

## QKV到注意力前缀流水

新增 `qkv-attention-pipeline-balanced-map`：注意力改为工作组32..63，避开QKV权重RF的覆盖。每个batch成员的前半段需K/V前32位置（QKV tile3/11），后半段需全64位置（tile7/15）；等待所有相关tile的全部ST事件。最后一条ST不保证之前异步ST已完成，最初版本仅依赖last-ST，被公共HBM race检查拒绝，保存为`*-incomplete-events`；修正版两个seed功能与竞争通过。新增名称压缩处理具体循环event引用；不修改评估器。

硬件最多每SM4组保持满足。第二个batch成员的最后16个工作组SM映射做xor1，使较重的后半段与另一成员较轻的前半段配对。原先两个较重半段都落在奇数SM，存在负载不均。映射变更也作用于之后W2/归一化，必须完整验证，不能只看注意力核。修正版第一完整层计时进行中，尚无完整score。

`stream-n64-w2-prefetch`在每个流式K阶段结束后发真实RF标记事件，每阶段提前填两个W2 bank，两个seed通过；尚无计时。初版W1本身较慢，不能把预取假设当成已确认收益。

## D1四段注意力与SH历史缓存

`d1-seg4-sh-history`将每头8个16-key分段改为4个32-key分段，仅前16组执行注意力；QKV、WO、FFN仍为32组既有分工。历史K/V两层共4096float/attention组，即16KiB，缓存到私有SH。K/V先后通过空闲RF12/13读取，避免1024float历史块覆盖RF15中的scores/临时量。每SM2组各申请16KiB≤32KiB；恢复SH32KiB/4bank，并把DMA2降为DMA1，总面积23.84637760512mm²。两个seed D1数值与竞争通过，完整D1计时38123、18.46047W，慢于32737，淘汰。

这个方案降低部分meta/context HBM写入、后续合并规模和活跃注意力工作组数，但增加每token的SH→RF读取，且降低DMA并发。数学上不能忽略这项代价：若更长分段只把相同历史字节改为串行加载，收益可能被抵消。

## 计时结论与后续筛选

QKV前缀流水+balanced map第一层83959cycles、21.3868822302W、HBM读取7000064bytes；归约padding对照83543/19.4806151589W，源读取约6008832bytes。流水使不同WG读相同数据的issue_cycle变化，损失源multicast，且独立WO加载更集中。即使图资源下界下降至188780，也没有转化为可行时间，不能用下界直接宣称八万分。

新`attention-balanced-map`仅将原attention第二个batch成员（WG16..31）SM映射xor1，让较重后半段与较轻前半段配对；QKV/WO保持原映射与屏障，W2及norm仍为原映射。两个seed P1通过，原版/新映射的第一attention前缀完整计时为25764/25480周期（仅改善1.10%），两者17.7235517642W、HBM读取2052096bytes。未做完整grade，不报新分数。需区分跨阶段流水失败与纯负载均衡是否有效。

62982.58相对62270.94仅改善1.14%，并未解决八万分的主要差距。当前TP×TD=10174201282，八万要求≤6306106155.2875，仍需减少约38%。要有大幅收益，必须同时压缩P1批次/阶段调度空闲与D1冷/热两段的串行依赖；每个方案都需先功能、局部功耗/耗时，再完整双案例精评。

完整62270报告的资源统计：P1最大单SM RF读busy153034、TC89298、全局NoC180142，相对317930周期都存在大量空闲；D1最大RF读11192、TC8848、NoC11702，相对32737周期也非硬件全程饱和。busy是实体周期，不是可直接相加的关键路径。调度空闲有改进空间，但容量下界不包含数据到达、循环依赖、multicast时机和功耗，不能据此保证最优解。

## 下一轮模型和决策

当前没有经过完整精评验证的八万分方案。有效布局修复已产生完整62982.58分；另外6类变化未提供足够大且满足约束的收益。不把多个候选的局部最佳值拼接为分数。

筛选模型须同时表达：(1)按指令的依赖和各SM资源排队；(2)RF bank/位置容量与读写hazard；(3)HBM地址通道映射floor(addr_bytes/256)%8；(4)源multicast键(issue_begin,line)及独立目的NoC字节；(5)1000周期滑动功耗窗口；(6)每个异步HBM ST的完成事件，不能把最后一条ST视为全队列已完成；(7)D1前一步commit后才释放下一输入。当前资源下界只能排除差方案，不能代替调度求解。

真正能覆盖38%乘积差距的候选，至少需要例如P1≤250000且D1≤25000，或P1≤260000且D1≤24000。应优先研究保持同源同步读取的跨阶段局部流水，以及消除跨组中间量的重新分工；不能继续单独增大并发。任何更大的全批RF常驻/块融合必须先证明bank容量与中间量传输不增加。本轮N64流式权重虽容量可行，但耗时证明单组调度和等待代价大于传输收益，不能沿用“输入字节减半即快一倍”的粗估。

纯映射改善仅1.10%前缀，保留为低风险备选；若下一轮采用，也必须再做完整P1/D1 grade。所有本轮计时进程均结束，没有待完成的精评被当作成绩。
