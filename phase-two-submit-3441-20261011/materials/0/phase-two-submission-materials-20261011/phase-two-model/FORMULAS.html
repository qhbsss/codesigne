01 · 先搞清楚：模型究竟有几层？

数学优化对象是一套共享硬件 + 每个场景一份生成的静态程序；不是把一条拟合出来的“预测周期公式”直接交给求解器，就自动得到所有合法程序的全局最优。

① 有限菜单选择共享硬件 H、各场景策略 θ；固定工作负载、权重、种子。
② 生成程序由官方生成器导出 P，再从实际付费指令取资源下界 L。
③ 解主问题共享硬件 x 与逐场景软件 y 的 MILP；未验证项只使用安全下界。
④ 上界与预测安全下界先证明某门槛是否不可能；否则用独立估计 Ť 筛查。
⑤ 真正验收同一程序 SHA，精确时序/功耗、FP32 参考检查、五场景评分。

理想设计问题

在所有合法硬件和所有合法程序中找最高正式得分；包括尚未参数化的布局、融合与任意指令序列。目前没有完整展开成独立可解的MILP。

真正落地的求解问题

先声明有限硬件/软件菜单，再用生成器为每个选项产出程序；主问题对此有限域可求解，下界与官方验收可形成有条件的有限域证书。

03 · 硬件模型：选器件规格与数量，不选物理排布

硬件 H 是芯片资源配置向量：SM 数、每个 SM 的计算引擎数量/宽度、RF/SH 容量与端口带宽，以及芯片层 HBM/NoC/Cache 容量和功能开关。23 个字段中，有些是数量，有些是尺寸、带宽或是否启用，不能笼统理解为“每种器件的数量和排布方式”。

H=(H1,…,H23),Pc=Gc(H,θc)

数量与规模

sms、tc_count、dma_engines、hbm_channels 是数量；p/q、vector/sfu 是计算形状或宽度；rf_kib/sh_kib/cache_mib 是容量；rf_tier/sm_noc/global_noc/sh_tc_bw 是访问或互联带宽。容量变大不意味着排布改变。

排布与拓扑的边界

每个 SM 被视为同构实例，硬件配置没有“TC 放在第几个 SM”“SM 间连线矩阵”“片上线路的物理坐标”这样的变量。sm_noc/global_noc 控制带宽，不是网络拓扑；multicast 是功能开关。工作组落到哪个 SM 是程序的静态归属，不是器件物理排布。

理论上 23 个字段可以从合法菜单选值；具体一次求解只改变事先声明的子集。小例里仅 hardware.rf_tier∈{1,2} 可选，其余 22 个字段均固定。同一 H 供所有场景共享，硬件面积与静态组合规则必须通过校验。

04 · 软件模型：生成什么程序，而不是改写硬件仲裁器

每个场景 c 有自己的策略 θc。官方生成器把它和共享硬件 H 变成静态程序 Pc：决定计算怎样分块、选择哪些算子实现、数据怎样打包或复用、有哪些 wave、每组绑哪个 SM、申请多少 RF/SH，以及指令、DMA 与 wait/token 的顺序。软件决策会改变调度的输入，但不是动态调度器本身。

程序设计可表达的调度

例如 policy.m 改变 GEMM 行分块；split_k 改变 K 维并行与合并；parallel_groups、async_prefetch 改变并行与异步指令安排。每个导出组有 sm、rf_kib、sh_kib、commands 字段。

运行时调度仍由模拟器决定

同一 SM 多组同时就绪时，谁先发射、DMA 队列何时空闲、端口何时释放、HBM/NoC 何时返回，由固定调度/内存状态转移规则按执行状态决定；policy.m 不是“直接指定第 812 个周期运行哪条指令”。当前 MILP 也没有把每条指令的 PC 和每周期发射作为决策变量。

05 · 可行性约束：为什么不能只看“更快”

硬件离散菜单与组合规则

xj,k∈{0,1},∑k∈Djxj,k=1

这是 23 字段有限菜单的一种数学描述；当前代码的主 MILP 并不直接放入全部 23 组 one-hot，而是先枚举规格内合法的共享硬件 h 再用 xh 选择。静态规则包括 SFU≤Vector、TC 开关与形状必须相容、SH 关闭则 bank/interface 关闭、SH→TC 必须有 TC、面积≤100 AU。

面积的完整独立结构式

令 N＝sms、R＝rf_kib、t＝rf_tier、V＝vector、U＝sfu、c＝tc_count、kp＝tc_k_parallel、SH＝sh_kib、b＝sh_banks、u＝shared_ports、Bt＝sh_tc_bw、r＝reduction_units、z＝dma_depth、d＝dma_engines、G＝resident_groups、Bs＝sm_noc、Bn＝global_noc、h＝hbm_channels、Q＝hbm_queue、C＝cache_mib，m＝1 表示 multicast。RF 档位面积系数 ft∈{1,1.6,2.6}。

aSM=0.45+0.018V+0.06U+c[0.072+0.008(pq+p+q)kp]+0.018Rft

面积单位 AU；绝大部分变量增大都会消耗面积预算，绝不能同时取各自的最大档位。靠近 100 AU 的浮点边界由官方 validate 作最终裁决。

每个 wave / SM 的实际并驻容量

∑g∈𝒢w,srg≤RKiB,∑g∈𝒢w,shg≤SH,|𝒢w,s|≤G

𝒢w,s 是 wave w 固定到 SM s 的组；rg、hg 是导出程序实际申请的 RF/SH KiB。仅校验 parallel_groups≤resident_groups 不够：实际导出的组会因为分块尺寸或布局超出 RF/SH 容量。

06 · 时间与功耗：计算子集的独立公式 ≠ 完整程序的独立精确模型

计算微步骤（无 DMA 时独立建模）

一条指令展开为若干微步骤；每步依次经历 read → core → write。RF 档位 t＝1/2/3 对应读带宽 BR＝128/256/512 B/周期、写带宽 BW＝64/128/256 B/周期。SH 的 bank 服务时间还依赖具体地址和冲突，不能只用“总字节÷总带宽”。

ℓRF=2+⌊log2⁡(max(R/32,1))⌋,ℓSH=6+⌊log2⁡(max(SH/4b,1))⌋
DRFread=𝟙v>0(⌈v/BR⌉+ℓRF),DSHread=𝟙v>0(νread+ℓSH)
DTC←SH=𝟙v>0(νread+ℓSH+⌈v/Bt⌉+2),Dstep=max{DRFread,DSHread,DTC←SH}+Dcore+max{DRFwrite,DSHwrite}
Tserial-wave=1+∑i∈instructions(1+∑s∈steps(i)Dstep,s)

νread/write 是按实际 bank 地址求出的服务周期；写路径使用对应写带宽/写冲突。Fill、Vector/SFU、Reduce、MMA 和 SH Copy 的微步骤已独立实现；MMA 按 p×q 物理块与 K 并行粒度计 padding、读取与 drain。上面的串行式只对单组、无 DMA、无其他组资源竞争的受限场景是独立精确式。

完整程序的真实运行可表示为“状态转移”，不是当前 MILP 的显式约束

(zk+1,Δtk,𝔈k)=FH(zk,Pc),Tc=∑kΔtk
P0=0.025A(H)+0.15h,PW=P0+maxτ∑eEede|[se,se+de)∩[τ−W,τ)|2000W

上式 PW 中 Ee 使用 pJ、时间使用 500 MHz 的周期；e 遍历服务区间能量事件，W 分别取 100/10,000。zk 包含组 PC/token、SM 端口和引擎、DMA 队列、64B HBM 请求/250 周期就绪、通道 credit、Cache 标签/LRU/MSHR、NoC 与功耗事件。

关键区别：完整时序 runtime 与官方评估共享同一个调度/内存/功耗状态转移内核；两者同周期不意味着“另写的完整独立数学公式”零误差。独立微步骤与计算子集已有对照，完整通信预测另见下节。数值正确性只由完整 evaluate 判断。

这样抽象，能不能“完全模拟真实运行”？要分三个问题

已选 H、已生成 P：教学模拟器的时序

可以。给定确定的程序和输入配置，使用包含全部队列、端口、Cache、HBM、NoC、功耗事件的官方状态转移内核 FH，就能按其规则得到该教学模拟器的精确周期/功耗；但这属于运行仿真，与官方评估共享核心，并非独立公式从少量变量直接算出了结果。数值与参考比较还必须单独运行完整评估。

只给 H、θ：独立数学模型直接预测或优化

目前不能保证完整复现。H、θ 先通过生成器变成程序，程序内具体地址、资源请求顺序和历史状态决定后续命中、排队与竞争；主 MILP 没把 FH 的全部状态与逐周期转移变成可求解约束。独立 Ť 是近似，安全下界 L 只用于定界，不是完整执行时间。

理论上可以把教学模拟器的有限状态和程序指令逐项写成庞大的混合整数/离散事件约束；“可数学表达”不代表“已展开且能高效求全局最优”。如果“真实运行”指物理芯片，教学模拟器还缺实际工艺、时钟漂移、温度与真实内存系统校准数据，连运行仿真也不等于硅上实测。

07 · 保守时间下界 L：用来证明，不是用来预测

每个候选先导出实际付费程序并展开 wave；计算出资源占用下界 Lresource，以及组内前序/异步 token/wait 的依赖路径下界 Ldep。不同资源可能相互重叠，因此每个 wave 取最大值；不同 wave 不重叠，因此跨 wave 求和。

Lresource=max{1,ncommit+∑w[1+maxs{Iw,s,⌈Ww,s,e/Ce⌉,⌈Rw,s/BR⌉,⌈Dw,s/BW⌉}]}

I：该 SM 的命令发射数（含 wait）；W/C：计算引擎核心总占用/该 SM 上引擎实例数；R、D：非 DMA 计算指令 RF 必付读/写字节。末尾 +1 是 wave fence。这里故意不把可能命中 Cache 或重叠的 DMA 流量硬塞进“可证界”。

第二项沿每组程序顺序传播最早完成时间：对于非 DMA 计算指令，微步骤的 core 和 RF 读写最小 service 周期相加；没有 Cache 且确实读 HBM 的 load 至少有 250 周期 ready；异步只创建 token，wait 与组 PC 取最大。每个 wave 取组内最长必经链。

dcompute=∑step(Dcore+⌈vread/BR⌉+⌈vwrite/BW⌉),Lh,c,a=max{Lresource,Ldep}≤Th,c,a

这个不等式才可以用于数学最优性证书，但通常很松。小例最优候选 L＝11,446 周期、T＝23,616 周期，T/L≈2.063；原纯资源下界只有 597 周期。“下界差 2 倍”绝不是“预测值误差 2 倍”：预测值是另一套独立估计 Ť。

08 · 独立完整周期估计 Ť：给候选排序，不给最优性证书

model/estimate.py 流式展开 compact 的 repeat/template/仿射地址表达式，按组 PC、SM 发射端口、计算及 DMA 引擎、异步 token/wait 排列事件。计算单指令时长来自上面的独立微步骤；DMA 近似加入 HBM 250-cycle 就绪、行到通道的映射和带宽。

DMA 指令 d 的地址按 16 个 word 批处理；Nd 是去重的 64B 行数，Nd,h 是通道 h 上的行数，Ed 为元素数。Fh 是该通道的预留完成时刻；td 是已满足发射/引擎约束后的开始时刻。

Ad=td+1+6+250+𝟙store(ℓlocal+1),Fh←max(Fh,Ad)+2Nd,h
Rd=max{⌈Ed/16⌉,⌈Nd/2⌉,⌈(72+8𝟙store)Nd/Bsm⌉,⌈(72+8𝟙store)Nd/Bglobal⌉,⌈4Ed/Blocal⌉}
C^d=max{maxhFh+7+ℓlocal,Ad+Rd}+270bd𝟙store,T^c=ncommit+∑w[C^w+Kw+1+20𝟙DMA(w)]

bd 是同一写指令相邻 16-word 批重复触碰尚未 ack 的行数。对不同组同写一行，模型构造冲突图：最大写者数 mw、相邻写者去重边数 ew、每 SM 最多并驻组数 gw，增加经验等待项：

Kw=min{d,gw}max{260(mw−1),⌈260ew/4⌉}

当一个 wave 有 ≥128 条 DMA、且没有相邻批重复写行，还会用通道总量和每 SM 计算尾部对原逐指令时长作流体吞吐修正：

C^w=min{Cw,max{2maxh∑d∈wNd,h+310⌈Dw/N⌉,maxsCw,scompute}}
预测值不能充当约束：270/260/310/20 是有限样本校正量，不是可证明物理常数；长 DMA 的 HBM FIFO/credit、Cache 命中与 MSHR、多播、NoC 双向拥塞、功耗与 FP32 数值都没被完整展开。即使 Ť 接近某个实测 T，也不意味着对未见候选的误差被保证。

09 · 整数规划主问题：变量、约束、提案、证书

把规格事先声明的合法硬件集合记为 ℋ；硬件 h 与场景 c 对应的生成器策略菜单记为 𝒜c(h)。xh＝1 表示只选该共享硬件；yh,c,a＝1 表示场景 c 采用该硬件下的策略 a/生成程序 Phca。不是两个场景各有独立硬件。

xh,yh,c,a∈{0,1},∑hxh=1,∑a∈𝒜c(h)yh,c,a=xh (每个 h,c)
∑hA(h)xh≤100,yh,c,a=0 若已证实该选项违规

没有时序验证之前，从静态程序计算常数 Lhca；选中并完成官方数值/功耗验收后，该项改用真实周期 Thca。模型不以一个连续变量线性拟合 ln(T)：它预先把每个离散选项的系数算好，然后一次次解线性整数规划。

确认数值、功耗、静态规则失败才能将对应 y 禁用；超时/异常不等于数学意义上的不可行。主问题由 SciPy/HiGHS 求解，其对偶下界 Bk 与已经完整验收合格的最好成本 Uk 构成可验证区间：

Bk≤J𝒟★≤Uk,gaplog=Uk−Bk

若各场景互不共享运行状态，固定 h 后可逐场景最小化预测周期而不丢弃该有限域内的预测最优组合：枚举规模由 ∏c|𝒜c| 的完整组合减少为 Σc|𝒜c| 的单场景预测。

minh,ac∑cwcln⁡T^c(h,ac)=minh∑cwcln⁡(minacT^c(h,ac))
先证明，后估计：对于正目标 K，主 MILP 的安全成本下界 B 给出分数上界 Supper＝1000×exp(Σwc ln Rc−B)。若 Supper<K，整个声明的有限程序域都不可能达到 K，无须调用独立估计或评分器；这不排除域外程序。否则才用所有选项的 Ť 再解“条件预测最优” MILP：预测低于 K 时停止、不评分，但不能据此证明目标不可能。

10 · 真实小型实例：每个变量和约束怎样落在数据上

这不是虚构的玩具数字：规格是 specs/small-two-case-model-first.json，数据来自对应 preparation.json 和 solution.json。两个场景 case-a / case-b 使用同一小型 workload，各占 1/2，固定公开种子 7。它们只是解释 MILP 的测试场景，不是五案例正式打分输入。

步骤 A · 将离散硬件与软件菜单展开成变量

硬件 h1 的 rf_tier=1、面积 76.61029301283328 AU；h2 的 rf_tier=2、面积 87.66949301283327 AU，其余 22 字段共用基础配置。每场景 a∈{m=2,m=4}，因此只有 2 个 x 与 8 个 y，共 10 个二元变量，程序层面 2×2×2＝8 个联合组合。

A(h2)−A(h1)=8·0.018·128·(1.6−1)=11.0592 AU

两种面积都≤100 AU。因为硬件必须共享，这个小实例中 MILP 的全部链接/面积条件可具体写成：

x1+x2=1;yh,c,2+yh,c,4=xh (h=1,2；c=A,B);76.610293x1+87.669493x2≤100

对应 HiGHS 实例一共有 6 行约束：1 行硬件 one-hot + 4 行场景链接 + 1 行面积；所有变量上下界在 [0,1] 且整数。

再看实际程序与验收：选中的 case-a.jsonl 展开后第 1 个 wave 有 4 组，分别落在 SM 0～3，每个占 RF 1 KiB、SH 0 KiB；例如 SM 0 上的 (RF,SH,组数)＝(1,0,1)，逐项满足 (128,128,2) 的容量界。官方同一程序结果给出面积 87.669493 AU、HBM 峰值分配 13,632 B、100 周期窗口峰值 5.798385 W、10,000 周期窗口峰值 3.502480 W、总周期 23,616，均小于相应门槛；192 个被比较元素的最大绝对误差 4.7684×10−7，数值检查通过。这些动态值来自正式验收，不是 MILP 预先推得的可行性保证。

12 · 与真实运行的 gap：哪些已经被表达、哪些还没有

层次当前可以做什么尚不能从模型推出什么
硬件23 字段合法菜单、面积与基础功耗独立计算。面积边界最后几 bit 与全部硬件组合的穷尽证明；未声明的硬件配置不会进入该次有限域。
静态程序/算法按声明策略生成真实 JSONL，抽取程序级资源和依赖约束。任意指令重排、在线 attention 归约、布局与融合、跨 wave 缓存等尚未作为可生成且可约束的变量。
计算与通信无 DMA 计算子集有独立微步骤；完整程序有独立 DMA/HBM/NoC 近似。完整程序的独立逐请求精确 Cache/LRU/MSHR、credit、FIFO、NoC、多播竞争状态方程和全域误差上界。
功耗/内存/正确性逐 wave 静态容量必要条件可检，完整验收给出功耗、HBM 峰值和公开种子数值检查。MILP 中的普适滑窗功耗、动态峰值、FP32 误差与任意未见输入可行性证书。
最优性有限域中以安全 L 为下界、已验合格 T 为上界；小例可得到零 gap。五场景真实最优证明、5000 的不可能性证明、任意合法程序的全局最优和真实芯片性能预测。
下一步才真正可能提高目标分：扩大可生成的策略变量/程序族并保持每项可被静态约束；改进仍然保守的通信/依赖下界以缩小 L 与 T；对过 5000 条件预测门槛的同 SHA 程序做完整评分。仅仅把 597 周期下界改写成“597 周期预测”，或把小例零 gap 套到五场景，都会误导。
