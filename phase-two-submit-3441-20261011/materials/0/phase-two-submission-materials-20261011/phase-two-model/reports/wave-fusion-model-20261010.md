# 在验证之前声明的相邻 wave 调度模型

## 性能瓶颈与新求解变量

旧 `k4-rf` 的独立事件估计将 `w-d4l` 的 55,586,140 周期拆成纯搬运 wave **30,731,016**、含MMA的 wave **23,220,168**、其余 **1,634,952** 周期。对应 wave 数依次为 12,552、1,752、112；前一类搬运与多个矩阵输出块在连续 wave 间硬性栅栏。因此只调每SM器件数量或矩形M/N仍未越过五千分门槛。

新变量 `f_c∈{1,4,16,64}` 是场景 `c` 的**最大相邻独立 wave 融合数**，而不是修改权重、数值算法或模拟器。每个候选静态程序由已有合法JSONL确定地转换：只合并同一组SM/RF/SH预留、相同全局只读与写入张量集合、且纯DMA或含MMA的相邻wave。所有写张量不能在同一wave中被全局读取；同张量写视图按逐行全局区间证明互不相交；非wave记录、不同类别、未证明安全的依赖都阻止合并。每个组按原顺序拼接命令，异步token重编号确保每个wait引用其原来的操作；限定融合后的命令上限。原来的指令、计算次序、张量输出与请求本身不变，改变的是原先wave fence施加的**跨组调度顺序**。

实现后又根据程序的实际wave类型扩展了上述初版声明：`m_c∈{concat,pack}` 表示连续波次的组内顺序拼接，或在共享硬件允许的RF/SH和`resident_groups`容量下并驻原来的组。除DMA/MMA外，向量和归约wave同样可以检查。对于同一张量的原地读写，记录每行读取/写入的保守全局区间，并要求不同原wave之间的WAW、RAW、WAR区间均无交集；同一wave内部读写允许按照原有指令顺序执行。pack不重编号不同组之间的token，concat只对同组的新异步token重编号。逐条检查所有原wave的组布局和操作集合一致，释放、分配、输入、提交记录始终断开合并。

形式化令`R_{i,t}`与`W_{i,t}`为原wave `i`读取/写入张量`t`的字地址保守区间集合，融合分段`b`内每一对`i<j`满足`W_{i,t}∩W_{j,t}=W_{i,t}∩R_{j,t}=R_{i,t}∩W_{j,t}=∅`。pack选项另满足每个SM上的`Σ_g RF_g≤RF_SM`、`Σ_g SH_g≤SH_SM`、`Σ_g 1≤G_resident`；concat保持原组数与预留。整数规划选择共享硬件二进制`x_h`及每场景局部二进制`y_{h,c,f,m}`，约束`Σ_h x_h=1`、`Σ_{f,m}y_{h,c,f,m}=x_h`、`Σ_h area(h)x_h≤100`，按同一套实际生成程序的独立周期估计最小化`Σ_c w_cΣ_{h,f,m} y_{h,c,f,m} log T_hat_{c,h,f,m}`。若不能证明读写独立，转换保持原fence；通过全量数值模拟后才可声称功能正确。

较大教学样例`batch=4,prefill=16`静态程序融合前含158个wave：串联模式融合后56个wave，官方公开种子数值对照通过，真实周期由134546降至133128，独立预测127612（低估约4.1%）；提升并驻上限为4后pack模式融合为69个wave，官方数值对照亦通过，真实周期120547，独立预测121789（高估约1.0%）。这两个小样例仅验证规则与估计方向，既不是正式五场景分数，也不保证较大波次的功耗一定合法。正式有限域分别在`specs/k4-rf-fusion-target-5000.json`与`specs/k4-rf-pack-target-5000.json`预先声明；仅当独立预测达到5000且同一程序SHA不变时运行完整五场景评分。

进一步研究的组内流水模式`pipeline`允许不同wave依赖同一个组自己的结果；只有此前其他组的读/写区间与当前组写/读不交叠才撤销跨组fence，且两wave的组布局必须一致。组内拼接保留原有指令顺序，所有未能证明的跨组依赖原样保留。数学上改为仅对组号`g≠g'`检查`W_{i,g,t}∩(R_{j,g',t}∪W_{j,g',t})=∅`、`R_{i,g,t}∩W_{j,g',t}=∅`；同组的先写后读由程序次序保护。上述教学样例`pipeline,f=16`融合为44个wave，官方数值检查通过，真实周期133039、独立估计128326；小规模样例并未表现显著加速，不能提前假设五场景同样有效。

另一独立软件变量是原生成器`parallel_groups∈{2,4}`：在同一份新增`resident_groups=4`硬件上重新export，不与上述仅重排旧命令体的程序混同。它通过`specs/k4-rf-parallel4-target-5000.json`预先定义五案例32种组数组合，使用相同的保守下界、独立预测与MIP择优。对旧命令体的融合与重新export出的不同命令体必须分别记录SHA，不能相互代用验证。

新增的候选生成策略是 decode 初始 K 矩阵布局转换的转置块`r_c∈{16,32,64,128}`。原始程序在每层开始时对`batch·D×history`的矩阵用16×16个FP32元素复制到持久化K布局；每个16×16块消耗一个DMA工作组及一次双向HBM搬运。对相同的输入张量、输出张量和所有字地址一一对应的排列，改用`r_c×r_c`，缩小wave栅栏与DMA启动次数，但更大的单组RF、SM争用和行列跨距也可能**增加**耗时。合法约束为`4·min(r_c,batch·D)·min(r_c,history)≤1024·RF_kib`、每wave同SM分组RF之和≤RF容量、组数≤并驻上限、单DMA≤16384元素；每块全局地址从原始矩阵`(row,col)`分别读取`col·batch·D+row`，写入`row·(history+steps)+col`。需要对**完整候选程序**计算独立预测，不能按减少块数比例推测提速；短decode教学样例tile=16/32/64的真实周期分别134700/140471/191636，大块反而更慢，因此先以正式场景独立模型筛选，若预测不能提升立即保留原块。

正式`w-d1`的`r=128`初始转置从3072个原wave降为48个新wave，但独立完整周期预测反而从原硬件上的约18677500增至**29622556**，增长约58.6%。生成程序保存在`runs/transpose-probe-20261011/w-d1-t128.jsonl`，输出前还未进行本候选的正式数值验证；严格按模型筛查规则不拿它触发五场景评分。这个反例表明wave数不能代替目标函数：大型转置指令导致分组RF占用、单组串行访存和跨距服务成本增加。

有限域硬件-程序协同候选`specs/k4-rf-shared-panel-target-5000.json`采用**同一**RF64/SH128硬件，另在MIP中选`(p,q,kp)∈{(16,16,2),(16,32,1)}`和五个场景分别的软件分支：prefill`sh_rows∈{2,4},sh_direct=true`，decode`(sh_rows=2,sh_direct=true)`或`parallel_groups=1`。它依据`gemm_shared`将一块B矩阵常驻SH，减少不同输出行读取同一全局B板块；B板块和SH累加暂存分别满足`K·N+r·M·N≤SH_kib·256`，RF staging和同SM双组之和也须≤RF64/SH128。两套硬件面积分别99.4903与98.4663 AU。较大教学prefill样例在前一硬件上`sh_rows=2`的官方FP32验证通过，周期由134546降到92135、独立估计91370；此单例不保证正式五场景达标。对上述2×2⁵个声明组合，先生成候选并计算保守下界与独立五场景MIP条件预测，未达5000继续扩展算法；达到门槛才检查同SHA的完整官方评分。

现已完成前两套五案例有限域MIP预测，**尚无本轮正式实测**：`runs/k4-rf-fusion-v2-target-5000-20261010/screen.json`串联合并因子均选64，条件预测**2858.9016分**，各案周期约45.976/127.101/11.388/18.563/29.232百万；`runs/k4-rf-pack-target-5000-20261010/screen.json`选择并驻分组后条件预测**2155.9653分**，未优于串联。正式`parallel_groups∈{2,4}`生成器搜索预测**2142.7953分**，w-p/a-p/w-d16的4组方案因RF/SH容量不足被拒绝。三者`official_score`均为null；与5000分别还有约1.75、2.32、2.33倍加权几何平均周期差，绝不把安全上界8798/10292误称分数。共享B板块配置的小规模FP32校验后进一步对教学样例串联合并因子64，官方数值正确且周期90722、独立预测89153；其真实五案例收益仍待本域模型求解。

继续扩大同一软件调度模型的融合上限为`f_decode∈{64,256,512}`，而非手调正式评分器。单个wave还须满足原有指令数≤65536、统计每条DMA全局视图的保守访问行区间≤262144，以及RF/SH并驻约束；达到任一上限自动断开合并，因此请求512不保证实际融合512个wave。逐个实际生成候选计算`T_hat_c(f)`，与固定prefill候选一起交MIP决定是否可达5000，未过线不进行正式评分。`f=64`已完成五场景模型预测，其余因子从耗时最大的`w-d4l`起先做独立估计敏感性检查，再决定是否扩大正式五场景域。

正式共享板块第一次静态容量诊断发现，`specs/k4-rf-shared-panel-target-5000.json`里的RF64双组方案虽然教学小案例正确，正式`w-p`却有RF36KiB的非GEMM工作组，两个同SM需要72KiB，因此模型准入**拒绝**，不能将小案例周期套到正式程序。保留这次未完成候选目录作为失败证据，改为预先声明`specs/k4-rf-shared-panel-rf128-target-5000.json`：RF128、SH128、vector64、SFU23/24，两个面积分别99.7463/99.2023 AU的共享硬件候选搭配上述逐场景共享板块选项，重新导出、逐wave容量检查与MIP求解，依旧保持5000预测门槛。

设 `B_c(f)` 为上述静态规则对场景 `c` 的连续wave确定的分区，每段中的组内指令顺序不变，合并后的独立事件时间模型为

`T_hat_c(f,h) = Σ_{b∈B_c(f)} estimate_wave(concat_commands(b), h) + N_commit`。

先对实际生成的候选程序建立保守下界 `L_c(f,h) = max(L_resource, L_dependency)`，再由HiGHS选择一个共享硬件 `x_h`、每场景唯一 `f_c` 的二进制选项 `y_h,c,f`，最小化 `Σ_c w_c log(T_hat_c(f,h))`；`Σ_h x_h=1`、`Σ_f y_h,c,f=x_h`、`Σ_h area(h)x_h≤100`，并检查每wave并驻RF/SH及指令上限。预测分依旧仅是 `1000*exp(Σ_c w_c log(T_ref_c/T_hat_c))`，下界转换的分数上界**不是预测分**。

只在五案例聚合条件预测达到5000时，才对选定的**相同SHA256**静态程序运行完整真实评分，检查FP32、资源、峰值功耗与实际周期；失败则依据误差修订独立模型，不能以近似预测领取5000成绩。本方法对未能静态证明无交叉依赖的wave只保持原有fence；未搜索到的其他指令布局不属于有限域最优性声明。

## 追加：跨类型流水融合与大因子敏感性

固定上一轮同一套99.9383 AU共享硬件，并保持输入及硬件配置不变，对实际生成的正式程序扩充三个场景局部候选：`w-p/a-p`各比较`concat-64`与已实现的`pipeline-64`；`w-d4l`比较`concat-64`与`concat-256`；`w-d1/w-d16`保持`concat-64`。MIP在这8种五场景组合中最小化`Σ_c w_c log(T_hat_c)`，而不是根据wave数量或单案例小样本人工选择。

| 场景 | 上一轮concat-64预测周期 | 新候选预测周期 | 新候选wave数 |
|---|---:|---:|---:|
| w-p / pipeline-64 | 45,975,981 | 45,748,677 | 122 |
| a-p / pipeline-64 | 127,101,111 | 123,022,555 | 652 |
| w-d4l / concat-256 | 29,232,108 | 28,755,564 | 1080 |

MIP选择以上三项和原有`w-d1/w-d16`程序，五场景条件预测由**2858.9016**提高到**2893.7978**，但距离5000仍需加权几何平均**约1.728倍**提速，故没有运行完整五场景评分。`runs/k4-rf-wave-hybrid-20261011/model.json`与`screen.json`留存目标函数、HiGHS解、完整候选SHA及预计周期；原始独立估计见`runs/pipeline-probe-20261011/`和`runs/w-d4l-fusion-large-20261011/f256-screen.json`。`f=256`在最慢decode上只提高约1.63%，不应将`f=512`无实验数据的改进预支为成绩；流水合并的正确性证明只针对已编码的静态地址区间，**尚未在这五个新程序上取得FP32/功耗验证**。

模型现在允许软件生成器参数`a_c`与融合因子/模式`(f_c,m_c)`同时作为整数决策。每个可行选项首先导出`P_c(a_c,h)`，再经静态相依检查产生`P'_c=Merge(P_c,f_c,m_c)`，最后在**同一实际生成程序**上计算`L_c`和`T_hat_c`。每个场景的选择约束变成`Σ_(a,f,m) y_(h,c,a,f,m)=x_h`；目标仍为`min Σ_c w_c Σ_(h,a,f,m) y_(h,c,a,f,m) log T_hat_c(P'_c,h)`，面积与逐wave容量约束不变。小型正式导出测试已经覆盖配置与融合的联合枚举及SHA续跑；新的生成器选项只有在五场景预测过线后才允许启动正式评分。增加离散选项并不能弥补尚未表达的在线attention、跨层权重复用及队列/Cache事件，有限域局部最优并非作业全局最优。

共享B板块的两套正式RF128/SH128硬件与逐场景软件选项已全部枚举并由HiGHS选择；条件预测最高仅**1459.6616分**，所选五场景周期依次为95,484,769、191,194,075、27,049,068、31,592,476、73,929,468，低于原来的串联合并候选。完整`runs/k4-rf-shared-panel-rf128-target-5000-20261011/screen.json`与`solution.json`显示`verified_options=0, official_score=null`；小教学样例提速无法外推到正式工作负载。因此这条软件支路**没有**触发正式评分，后续应聚焦更有效的指令体变换。

独立剖析将当前`concat-64`预测时间分解为：`w-p`含MMA wave约**41.43M/45.98M**，`a-p`含MMA约**67.18M/127.10M**、非MMA（主要是向量/归约）约**59.14M**，`w-d4l`含MMA约**19.04M/29.23M**。这解释了为何单纯消除剩余wave fence的收益有限。新增`model/reuse_b.py`尝试在输出区间不相交且读/写张量无交叉依赖时，对相同B板块的两项GEMM输出tile保留各自累加寄存器，只加载一次B并保持每项K累加顺序；RF预留和每SM并驻容量均在变换时检查。教学样例`batch=4,prefill=16`完成88对任务合并，官方公开种子数值输出SHA与原程序完全相同，独立预测**141340**周期，官方**141160**周期（高估约0.13%）；这是**小样例功能/时序校验**而非五案例成绩。正式候选仍需独立时序估计，只有五场景预测达到5000才可真实评分。

正式`w-p`原程序按16个原wave为窗口重组1984对tile，减少24,576条B板块加载；再经过串联因子64后，独立预测却由原来的**45,975,981增至46,211,619周期**（新程序SHA见`runs/reuse-b-probe-20261011/w-p-fixed-f64-screen.json`）。因此该软件变换目前**被目标函数筛掉**：少一次B加载不能抵销两份C累加器增加的RF资源占用、融合段被拆开及串行指令的代价。不能用教学样例的数值正确性推断正式程序提速，更不能在未达5000时执行五场景评分。

## 追加：等峰值阵列排布的联合求解

沿共享硬件面积与原融合后程序体，`specs/k4-rf-tc-shape-fused-target-5000.json`声明五种合法矩阵计算形状`(p,q,k_parallel)∈{(8,16,4),(16,16,2),(8,32,2),(16,32,1),(32,16,1)}`，分别对应99.9383、97.8903、98.9143、96.8663、96.8663 AU。输入五份程序的原始SHA与上一轮`concat-64`一致；每套共享硬件重写其五份程序头，重新检查容量、计算保守下界及独立耗时，然后由HiGHS选择**同一套**硬件和每场景唯一程序选项。`(16,32,1)`获最高条件预测**3102.5538分**，五案例周期依次为**33,233,061 / 115,604,623 / 13,362,352 / 16,185,812 / 32,811,628**；完整搜索墙钟约2549秒，保留在`runs/k4-rf-tc-shape-fused-search-20261011/{bound-screen,estimation,screen,solution}.json`。该域严格资源/依赖下界给出的乐观**分数上界11450.7051**，绝不能称为预测或实测分；`solution.json`标记`verified_options=0,official_score=null`，因为3102仍不足5000。当前要进一步提高加权几何平均速度约`5000/3102.5538=1.612`倍。改变阵列排布降低prefill的代价，同时可能使decode因小M而退化；单独优化w-p并不等于优化全场景目标。

针对大量数值相同但绝对寄存器/张量地址不同的计算指令，`model/estimate.py`与两个保守下界计算器改为按微步骤所依赖的尺寸、种类与操作数步幅做形状缓存；SH访存与`mma_shared`仍按完整地址保留银行映射。旧`w-p`与`a-p`的历史预测周期及资源/依赖下界在更换缓存键前后**逐项一致**，不是通过修改估计常数人为提高得分。完整模型测试集48项通过。

另将双TC并驻作为共享硬件离散变量单独声明为`specs/k4-rf-dual-tc-fused-target-5000.json`：两项面积分别99.9703、99.9063 AU，且同样保留五份源程序的付费指令体。独立估计与MIP选择`p=8,q=32,k_parallel=1,tc_count=2,sfu=16`，该有限域最高条件预测**2982.6721分**（`runs/k4-rf-dual-tc-fused-search-20261011/screen.json`）；比单TC阵列域的**3102.5538**还低。该实验也未触发正式评分；单一代表性GEMM wave更快，不能证明全场景聚合收益。

为避免把不同软件指令体按一次静态程序的参数虚构，`model/structured.py`扩展逐场景`program_choices`：每个程序来自已经生成的真实JSONL文件，校验原始工作负载/硬件头、输入及候选SHA；改写共享硬件头后重新计算**该程序**的容量、资源/依赖下界、完整独立预测，再交二进制MIP选择。`specs/k4-rf-tc-pipeline-hybrid-target-5000.json`在面积96.8663 AU的`(p,q,k_parallel)=(16,32,1)`上，分别让`w-p/a-p`选择`concat-64`或`pipeline-64`，`w-d4l`选择`concat-64`或`concat-256`，其余两场景保持`concat-64`。对全部**8**种静态组合求解后，MIP选中两份`pipeline-64`和`w-d4l`的`concat-256`；周期依次为**32,967,349 / 111,467,891 / 13,362,352 / 16,185,812 / 32,335,084**，五场景条件预测**3144.8955分**，比先前3102.5538提高42.34分。`runs/k4-rf-tc-pipeline-hybrid-20261011/{model,estimation,bound-screen,screen,solution}.json`留存目标、解、SHA与时间；其中乐观安全分数上界**11450.8547**不是预测分，`official_score=null,verified_options=0`，新方案距离5000还需约**1.590倍**加权几何平均周期提速。先前同程序族的历史1948.8761实测**不能**当作这里新SHA程序的真实分数。

因此当前的瓶颈不是MIP没有在所声明的8组合中找到更好的二进制解：该有限域的**独立预测最优**已找到；真正缺口在可生成指令体和精确通信/功耗事件。现有相邻wave融合、大因子与共享B组内复用不能替代跨tile/跨层复用或在线attention的算法级变换；任何下一代候选仍应先通过同样的容量、保守界与五场景预测筛查，过5000后才对**相同SHA**运行公开种子完整数值、功耗与评分。
