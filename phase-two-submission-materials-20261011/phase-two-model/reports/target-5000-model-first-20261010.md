# 五千分目标：模型先筛查，不以理论上界冒充预测或成绩

## 本轮模型与求解

正式五场景固定同一硬件，权重为 prefill 各 `1/4`、decode 各 `1/6`。模型决策为共享硬件二进制变量 `x_h` 和每个场景的软件程序二进制变量 `y_h,c,a`，要求 `sum_h x_h = 1`、`sum_a y_h,c,a = x_h`、`area(h) <= 100 AU`，按 `sum_c w_c log(T_c)` 最小化五场景条件耗时。目标得分是 `1000 * exp(sum_c w_c log(T_c_ref / T_c)) >= 5000`。程序执行顺序是导出/固定指令 → 建立安全下界 → MIP计算分数乐观上界 → 独立估计全部选项 → 同一MIP解出预测最优 → 仅预测过线才完整评分。下界和预测不是数值正确性证书。

`specs/k4-rf-target-5000-expanded.json` 声明共享 `k4-rf` 硬件、prefill 每场景 `m=32/64` 且 `parallel_groups=1`、decode 每场景 `split_k=1/4`。共有 32 种联合选择、10 个单场景程序；未使用已有程序的实测成绩来确定MIP目标系数。模型在这32组合中的**可证分数上界**为 **6146.2434**，高于5000，故不能证明5000在该域不可达。

独立模型计算并由MIP选出的**最高条件预测**仅 **1928.2968 分**，低于5000，正式评分器没有启动。墙钟 **1451.60 秒**，`verified_options=0`、`official_score=null`、`model_optimum_proven=false`。其预测分只是该32组合的估计最优，不是实际得分或真实全局最优。原有两组同硬件 `parallel_groups=2,m=32` 程序预测为1976.2252分；因此本次把prefill限制为单组，即使放宽到 `m=64` 也使估计变慢。

从本次1928.30的条件预测提高到5000，需要五场景加权几何平均耗时再缩短约 **2.593倍**。若暂把另三场景预测周期固定，仅让两项prefill达到各自**可证下界**，条件分也只有约2959.38；若固定两项prefill预测周期，仅让三项decode达到各自下界，也只有约4004.82。两者同时都达到下界才有6146.24的乐观上界。这是对固定周期的反事实诊断，**不是**未来任何新生成器程序或硬件的不可达证明；但说明单独调prefill tile或decode split-K不足以满足目标。

原始证据在 `runs/k4-rf-target-5000-expanded-20261010/`：`spec.json`、`preparation.json`、`model.json`、`bound-screen.json`、`screen.json`、`solution.json`。这些文件没有完整五场景评分报告。

## 共享硬件重配实验

`specs/k4-rf-replay-hardware-target-5000.json` 声明四种面积不超过100 AU的共享硬件菜单，以原有五份 `k4-rf` compact程序体为固定软件策略；每份新程序仅重配硬件头，保留源文件 SHA256 并检查逐wave容量。包含此前条件预测2142.4908的DMA2/SFU15硬件，以及DMA4/SFU8、DMA4/SFU15搭配不同NoC/HBM队列的方案。求解仍以安全下界、独立估计与共同硬件的MIP为准；头部重配方案不代表按新硬件重新 `export` 的另一套代码。原始建模和筛查结果保存在 `runs/k4-rf-replay-hardware-target-5000-20261010/`。

这四种候选硬件面积依次为 **99.9383、98.7543、99.8656、99.4263 AU**。保守周期下界得出的乐观最高分是 **8793.3150**，因此不能证明该域无法达到5000；独立模型+MIP解出的最高条件预测是 **2143.5316**，选中最后一套 `dma_engines=4,sfu=15,sm_noc=64,hbm_queue=32`，仍比目标少 **2856.4684分**，加权几何平均耗时还需约 **2.3326倍**提速。五个选中程序预测周期依次是 **47,225,399、140,322,435、18,715,144、26,366,900、58,370,532**。完整流程墙钟 **1982.83秒**；`verified_options=0`，`official_score=null`，**没有新的真实评分**。本结果比先前2142.4908的条件预测仅提高约1.04分；新方案的HBM队列缩到32，但独立估计**尚未逐事件模拟队列信用**，故此排名尤其不能当作实测优势。

## 双组并驻的矩形软件分块

`specs/k4-rf-prefill-rectangular-target-5000.json` 声明原有 `m=32,n=64,parallel_groups=2` 和 `m=64,n=32,parallel_groups=2`，由正式 `export` 各自产生两项prefill场景的新程序，decode固定基线。4种联合组合/7个单场景程序的安全分数上界为 **8573.9982**；独立预测MIP在两个prefill场景都选择原有 `m=32,n=64`，五程序SHA均与原 `k4-rf` 相同，最高条件预测仍是 **1976.2252**。两种矩形tile的已建模依赖/资源周期下界分别相同，不能单靠增大M证明减耗时；完整估计把候选排序为不优于旧程序。运行耗时 **1173.80秒**，`official_score=null`、`verified_options=0`，同样没有触发评分。

以上三次**有限域条件预测**的最高是硬件重配的 **2143.5316**，不是实际得分，也不是所有合法程序的数学最优。本项目早前同SHA `k4-rf` 五程序在公开种子上的真实成绩为 **1948.8761**，本轮没有重跑正式评分器；不得拿历史实测成绩给新头部程序充当实测。结果分别保存在 `runs/k4-rf-replay-hardware-target-5000-20261010/` 和 `runs/k4-rf-prefill-rectangular-target-5000-20261010/`，保留具体程序哈希、数学上界与MIP所选程序。

## 未建模或未验证的差距

- 上述有限菜单缺少在线attention归约、跨wave权重/KV复用、不同长KV布局和更深流水等可生成程序族；当前分数既不排除其他程序达到5000，也不证明任意合法ISA程序的最优解。
- 独立估计尚未逐事件精确覆盖HBM队列信用、NoC、Cache、峰值功率与FP32结果；模型下界虽然严格保守，却只在近似估计无法达标时阻止了本轮昂贵的官方评分。
- 若新候选未来预测过线，必须对**相同SHA256**的五个JSONL程序执行公开种子完整数值/功耗/时序验证，并报告预测与实测的误差，不能把6146上界或1928预测当作实际成绩。

下一步应先给程序生成器增加**真正改变付费指令体**的软件选择（例如跨wave B/KV重用、attention分块在线归约与decode长序列排布），对每个选择证明RF/SH/面积可行、以现有独立模型加上必要的队列/NoC代价预测，再以相同的MIP和5000门槛筛查；不是继续手动修改现有硬件菜单或把2143条件预测当成绩。
