# 阶段二：先建模、再求解、再验证

## 求解机制

`model/structured.py` 的 `model-first` 入口读取**一份事先声明**的硬件菜单及逐场景软件菜单，按共享硬件输出每个合法选项的静态程序，在运行时序/数值检查**之前**形成 `preparation.json`、`model.json`：面积、静态容量、可证资源/依赖路径周期下界与程序SHA256。HiGHS整数规划以共享硬件变量 \(x_h\) 和场景软件选项变量 \(y_{hca}\) 最小化加权对数周期下界；只验证求解器选中的选项，把已验证的真实周期代回主问题，再求解。运行失败/超时不会悄悄成为不可行剪枝；每轮MIP状态/对偶界、验证程序、完整数值结果和迭代日志均保留。

这是**模型先于求解、求解先于时序/数值验证**的可运行流程。没有人工按成绩修改参数再重跑，也没有把已有实测周期预填成模型系数。它仅证明输入规格明确列出的生成器程序域，不能优化尚未用软件决策变量描述的任意指令排列、attention融合或数据布局。

## 测试与测量

`specs/small-model-first.json` 含两个硬件RF档位 × 两个软件tile高度，共4个合法小型完整程序：每一程序的原有纯资源下界均为597周期；新增无Cache读取250周期ready和组内async/wait依赖路径后，界为 **11437–11488周期**。完整官方评估为 **23616–24152周期**，所有界不超过对应实际周期。这将最优程序的下界与真实周期之比从39.56倍缩小至约2.06倍，**不是说独立预测误差变为2.06倍**。MIP反复求解、完整官方数值验证后选中 `rf_tier=2,policy.m=4`，实际23616周期，声明域log gap=0；记录在 `runs/small-model-first-deps-20261010/`。

`specs/small-two-case-model-first.json` 含同一硬件下两场景各有两种独立软件选择，共8种联合组合、仅8个单场景选项。MIP自动选择 `rf_tier=2` 和两场景各 `m=4`；逐项官方验证后两个场景均23616周期，声明域log gap=0；记录在 `runs/small-two-case-model-first-20261010/`。运行 `python3 -m unittest discover -s tests -q` 可检验MILP硬件共享、因子链接、依赖下界、门槛拒绝及输出证书。测试使用项目声明的 SciPy/NumPy 依赖，本次在临时目录加载 SciPy，不更改系统环境。

**效率没有被虚构**：因为11437周期下界仍远低于约23616周期实际成本，小例中4/4、8/8个单场景选项最终均被完整验证。它不证明求解器已节省昂贵的评估工作；仅证明流程和有条件的有限域最优证书成立。要在真实五案例减少验证次数，需进一步构建更紧、仍保守的HBM/通信/依赖下界或有效割。

## 正式五场景范围

规格若设置 `target_score=5000`，系统在**已经完成模型准备**之后用独立估计器给所有选项作条件预测，另一共享硬件整数规划计算声明域最高预测分。若低于门槛，将报告 `below_prediction_target_unverified`，不会执行完整时序/数值评分或宣称最优性；若求解器另提一个低于门槛的候选，也必须报告未证明，而不能以未经证明的估计将其剪掉。只对模型先选出的相同程序SHA、且预测已过门槛的候选运行完整验证/聚合评分。回归测试用五场景模拟低预测确认门槛拦截。

正式五场景运行 `python3 -m model.tool model-first specs/k4-rf-casewise.json runs/k4-rf-model-first-cached-20261010 --timeout 600 --max-verifications 32`：**先**对固定共享硬件下32种组合/10个实际不同的单场景选项生成付费程序、各自计算严格资源与依赖下界、写入 `model.json`；**再**用共享硬件/场景方案MILP对10个独立估计周期求声明域最高**条件预测**，得 **1976.225235分**，五个选择的SHA与以前的 `k4-rf` 基线相同。全流程墙钟 **1552.27秒**。由于低于5000，`solution.json` 明确为 `below_prediction_target_unverified`、`verified_options=0`、`model_optimum_proven=false`、`official_score=null`；**没有新实测分数、没有新的正式数值验证、更没有模型证明5000不可达**。与先前`casewise`运行复用同一**声明的输入规格**，此次仍从零自动导出所有程序与建立下界，并非手动挑选已知最好的五套程序。

本有限域里各场景严格时间下界最小值依次为 **15263915 / 31858483 / 4171196 / 7201284 / 10555940周期**；这些界对应的乐观最高条件分仍约 **8731.98分**，高于5000。因而“独立估计1976分”和“保守下界允许8732分”共同说明：当前数学界尚不足以证明目标不可行，也无法在完整正式程序上直接推导出真实最优解。`runs/k4-rf-model-first-cached-20261010/preparation.json`、`model.json`、`screen.json`、`solution.json` 给出先后顺序及真实证据。准备期间发现大量重复计算指令剖析，增加基于完整指令内容的精确缓存；同一56 MiB预填充程序的旧资源下界不变，资源/依赖两遍下界计算实测分别约4.86/16.53秒，避免重复展开付费计算剖析。

后续最重要的建模空缺是扩大可编程软件解空间：让布局、跨wave K/V复用、attention在线归约和预填充/解码不同调度成为真实可导出程序的决策变量；同时给出有效静态容量、通信及功耗约束。现有`policy.m/split_k`菜单不代表所有合法指令程序，有限域gap=0绝不能包装成作业全局最优。
