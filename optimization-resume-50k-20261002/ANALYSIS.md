# Transformer codesign 5 万分优化续跑（2026-10-02）

## 起点与评分约束

读取历史汇总、30394 最终提交的原始官方 grade、50k 目录内 checkpoint、精评和粗估报告。
较早汇总中的 28885 已被后续 30394.215569735643 合格本地报告超越。本轮以该版本为起点，保留原目录不变。

- P1：611770 cycles；D1：71412 cycles。
- 面积：23.93570061312 mm²；P1/D1 峰值滚动功耗：16.935987/18.074404 W。
- 公开评分器为原版本；本轮代码只改 project 生成器、硬件 JSON 和候选 ASM。
- `score=1000*sqrt(30996995*1302032/(P1*D1))`。
- 50000 分要求 `P1*D1<=16143631757.536`，仅为起点乘积的 36.9523%。
- D1 保持71412时 P1需<=226063；D1降至57863时 P1需<=278997；D1若降至40000，P1允许<=403590。

## 方向分析与粗估方法

原静态粗估把整个程序的资源需求合并成一项最大值，忽略逐层/逐阶段的依赖链，以及 RF读、计算、RF写的串行服务。
例如把MMA M从8改成32，静态粗估仍给30394分，局部精评W1却有6.2%改善。因此不能把静态分数当真实总分。
本轮先检查功能与 race，再对关键 barrier 段做局部公开时序评估，最后使用完整官方grade。
局部阶段隔离时缓存冷启动、工作组数量和跨batch barrier不同；不能直接将旧的单batch段时间与新双batch段时间相加。

可能逼近5万的组合路径是 P1 约27万、D1约5.8万（约50830分），或 P1约40万、D1约4万（约50224分）。这只是所需性能预算，尚非已验证实现。
主要尝试：

1. 扩大MMA的M维，减少细碎LD/MMA与依赖链。
2. 每SM多工作组并行，按query行划分attention，按K/N划分W2。
3. 批次合并：两个prompt的dense算子用128行矩阵共享权重，attention仍严格隔离batch并保留causal规则。
4. FFN激活常驻RF，融合W1、GELU、W2；整块矩阵epilogue替代逐行处理。
5. P1新位置阶段从8个SM扩大至16个SM，并将W2拆成4K×8N。
6. D1 attention归并一次加载所有分段，用向量softmax缩放和MMA加权求和。
7. 向量/SFU并行度与RF容量共同重分块；矩阵尺寸越小不一定越快。
8. 初始化按权重种类对齐，尝试让相邻8列W2切片共享64B读取。

## 已确认局部结果

- m32：P1/D1功能通过；旧单batch W1段54765→51353（6.23%）。
- 8×8 TC、K并行4：D1 69184 cycles，18.06446 W，面积23.537965；较起点快3.12%。
- resident2：两个prompt各16工作组，每SM2组；W2为4K×4N；功能通过。新增普通GEMM的第二acc面板与lane7 epilogue临时值发生冲突，改至lane3并重验通过。
- fused8：W1/GELU/W2激活保留RF；功能通过。旧单batch融合FFN段73964，优势不足以单独达标。
- vector16：P1功能通过；D1 export曾覆盖新扩展RF缓存，改为独立lane15后通过。D1 compact merge精评57863 cycles、11.909129 W。
- vector8-block：整块epilogue、16SM新位置、compact D1；两项功能通过。双batch W1段41519 cycles、16.5889 W。
- vector16-block：功能通过；双batch W1段59091，较vector8差，排除。
- merged128：128行dense融合、32工作组、8K×4N W2；两项功能通过；W1段42393、18.068381 W。完整grade在运行。
- D1四段：功能通过，65614 cycles，18.073409 W，较八段compact差。
- vector32 D1：功能通过，59446 cycles、11.593249 W，较vector16 compact差。
- resident4：原源码超过8MiB，已压缩标识符得到8073328字节；尚未验证最终压缩版本，不作为交付候选。
